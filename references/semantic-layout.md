# 按语义选择组件与配图位置

本页由 gzh-design 第3.1步调用。Agent负责判断，脚本仅执行已确认结构和检查内容保真。

## 块语义

| 实际用途 | 呈现方式 | 标签处理 |
|---|---|---|
| 转述他人说法/用户反馈 | 主题引语或编者按 | 用具体来源/“使用者反馈”，无必要可省标签 |
| 作者提出的行动、收藏/转发引导 | 简洁行动卡或正文强调 | 可用“试试这样做”；不新增原文没有的互动内容 |
| 可直接发给模型的自然语言提示词 | 提示词卡，正常字号/行距，可复制纯文本 | “提示词”或内容用途；不整段等宽、斜体或套引语 |
| 错误/正确写法并列 | 对照组件或同主题说明卡 | “写法对照”；保留双方内容和顺序 |
| 建议替换的规则 | 操作说明/替换示例 | “替换句式”；不是作者引用 |
| 核心结论 | 重点卡 | 不多加撑高的空标签 |
| 代码、命令、配置 | 通用代码块 | 保留逐行内容和缩进 |

不强制每块都有标题；标签只在帮助理解用途时使用，不凭 `>` 一律输出“引用”。自然语言 Prompt 和代码必须分别判断，不能只看它提到了 AGENTS.md 就渲染为程序代码。

## 图片锚点

1. 打开每张图查看图内标题、流程、主体；同时读该图前后段落。alt 与文件名只供定位，不作结论。
2. 确定它解释的段落，默认放在说明之后、切换下一话题之前。概览图可在概览段后；操作流程图应在机制解释后；结果图紧跟结果案例。
3. 图注必须描述图中实际可见内容。图里没有 Verifier，就不能写“Stop Hook 与独立 Verifier”。
4. 记录图片路径、原位置、目标原文段落和理由。移动时只改变位置/已审阅图注，不删图、不重复图、不隔断代码块或步骤。
5. 验收文字顺序、代码逐行保真及新图序；先将位置/图注改动落实到本轮派生的 `_processed.md`，再针对它重新发起Stage6请求、装配与manifest验收；不拿旧源文的hash许可新图序。原始已发布稿保留作历史证据。

## 阅读节奏

Part切换留约一行额外空间，使用章节容器 margin/padding；不插空p、连续br或源码换行。正文行距以所选主题组件定义为准，用户要求稍增时小幅调整正文和导读，代码行距单独保留。禁止生成后用全局p覆盖破坏卡片。
