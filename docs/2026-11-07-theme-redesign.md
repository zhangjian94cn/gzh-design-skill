# 五套组件主题重设计与校验

本轮保留五个在役主题 ID，各自重新设计导读、章节和语义卡，正文以 16px / 1.9 为基准，留白主题使用 1.95；三级至五级标题通过字号、字重和间距区分。场景列由 [主题索引](../references/theme-index.md) 提供，缺省不推断。集成仓的 Spec 009 拥有完整用户故事与设备验收状态。

## 维护边界

- [通用组件](../references/common-components.md) 与各主题库拥有样式；[gallery](gallery/sample-article.md) 是同源全元素样张，主题之间不借成品 HTML 换色。
- 原生片段新增 `data-part` 语义部位标记；集成仓审核按部位读取当前库样式，继续验证主题、内容顺序及 source/library/html 三类摘要，避免字号一改就失去定位。
- 新样张清除 22 个重复无样式 leaf 包装，仅删除对应起止标签；有样式包装、文本顺序与代码空白保留。历史发布稿不改。
- 定向采纳上游纯色背景及原始 HTML 复制修复，保留本地可读性与原生结构；没有全面同步上游。复制事件直接写入原始 `text/html` 与纯文本，避免范围序列化注入样式；剪贴板受限时明确提示失败。
- [发布校验器](../scripts/validate_gzh_html.py) 按内联背景定位渐变警告（发布就绪检查仍保留原有阻断规则），不将代码里的转义示例误判为样式。

## 已执行验证与限制

本仓 tests 与 validate_gzh_html 测试：16 passed、30 subtests passed。集成仓的八主题浏览器矩阵与三类连续阅读样张覆盖这五套，截图及回读证据由 Spec 009 统一登记。五篇真实微信新草稿已通过冻结正文比较；每篇作者 Zhang Jian、评论关闭，仅保存草稿。

浏览器与 API 回读不证明 iPhone/安卓实际渲染或编辑器保存后重开的效果。设备观察仍为 manual_pending，不能将本次代码交付写成双端全面验收完成。
